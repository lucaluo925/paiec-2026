# ocr 审查：基准值修正与图表口径（2026-09-29 第三轮）

- 工具：`open-code-review` v1.12.10，`ocr delegate rule` 模式（代码不出本机）
- 范围：`train/fit_offline.py`、`eval/run_cv.py`、`eval/ab.py`、`tools/make_figures.py`
- 规则组同前：system `**/*.{py,pyi,ipynb}`

## High / P0
1. **收缩目标值的聚合口径与评分口径不一致**（已修）。
   `shrink.base_rate` 原来是把所有训练回答混在一起平均（micro），得 0.206；
   但官方评分是每个 subject-benchmark 组合等权平均，按同样口径算是 0.31。
   差距来自 `multi_swebench` 一家占了 74,445 条回答中的 57,808 条、且正确率只有 0.148。
   结果是零标签预测一直被拉向一个偏低的目标。
   - 发现方式：把零标签那一栏和固定常数比较，模型 0.2368，常数 0.30 只要 0.2160。
   - 修法：`train/fit_offline.py` 改成先按组合算正确率再等权平均（含 `r[2] > 0` 与空列表保护）。
   - 效果：诚实估计的零标签 Brier 0.2210 → **0.2184**，综合分 0.17702 → **0.17639**；
     收缩权重从 0.372 升到 0.523（目标值合理了，模型自然更愿意靠它）。

## Low / P2（已就地修掉）
1. **空数组上调用 `.max()`** — `tools/make_figures.py` 的 `brier()` 里
   `int(pid.max()) + 1` 在空记录上会抛 ValueError。实际不会发生（没有目标就不会有这一档），
   但按规则加了显式保护，空输入返回 `nan` 而不是崩。

## 已确认不是问题
- `run_cv` / `ab` 里新增的 pair id 偏移：偏移在同一次循环里累加，保证跨折唯一；
  越界会在后续 `bincount` 的长度上直接暴露，不会静默算错。
- `reliability()` 新增 `bscore` 参数：只有一个调用点，已同步更新。

## 已知的、**没有**去修的一处口径残留
`eval/tune.py` 的 `fit_shrink()` 仍用"所有预测混在一起"的最小二乘来选收缩权重，
而评分是按组合等权。方向和上面 P0 是同一类问题，但影响已经小得多：
修正基准值后，零标签 Brier 0.2184 对固定常数 0.2160，差距 0.0024，折算到综合分约 0.0002。
在只有 4 个 benchmark、折间差异高达 0.16–0.33 的情况下，为 0.0002 再改一轮调参流程
属于对噪声调参，按纪律不做。**已写进报告的局限一节，作为下一步的具体改进项。**
